# V1.1 RC12 — Production Readiness QA

## Alcance

RC12 es una release de entrega y performance **sin cambios de dirección visual**. Parte de RC11 y mantiene intactos SIGNAL → CLARITY, layouts, responsive, motion, Mi Sistema, Perfil y Contacto.

## Cambios

- La primera captura de CR Master (`crmaster-prospectos-light-real.webp`) pasa de `loading="eager"` a `loading="lazy"` y conserva `decoding="async"`.
- Las seis imágenes lazy que todavía usaban decodificación por defecto pasan a `decoding="async"`.
- Se conserva el contrato existente de `preconnect` para `fonts.googleapis.com` y `fonts.gstatic.com`; no se añaden hints redundantes.
- Se genera `assets/images/social-preview.jpg` desde el Hero real resuelto del portfolio: **1200×630**, JPEG progresivo, **83,131 bytes**.
- Open Graph incorpora `og:image`, tipo, dimensiones y alt; Twitter usa `summary_large_image`, imagen y alt.
- `assets/images/ls-top-icon.png` permanece como fuente de QA para el favicon y no está referenciado por el runtime de `index.html`.

## Decisión sobre URLs sociales

La imagen social se declara con ruta relativa para no fijar un hostname incorrecto antes de confirmar el dominio público definitivo. En el cierre de despliegue se deben normalizar `canonical`, `og:url`, `og:image` y `twitter:image` a URLs absolutas y después validar el preview real en los crawlers.

## Diff visual

RC12 no modifica archivos CSS ni JavaScript. El diff de `index.html` se limita a metadata social y atributos `loading` / `decoding`, por lo que no introduce cambios de composición o dirección de arte.

## Pendiente de producción

Cuando exista URL pública definitiva:

1. agregar `canonical` y `og:url`;
2. convertir URLs sociales a absolutas;
3. ejecutar Lighthouse en producción;
4. ejecutar Axe sobre la URL publicada;
5. registrar Core Web Vitals reales y ajustar solo con evidencia.
