# V1.2 RC1 — TKOH Evidence & Clarity QA

## Scope

RC1 inicia V1.2 sobre la release estable `v1.1.0` / RC13. El alcance está limitado al caso Studios TKOH / CR Master y su documentación/pruebas.

No se rediseña la identidad global. Se preservan `SIGNAL → CLARITY`, tipografía, paleta, navegación, Amazon Magic Park, 20 Prod., SUNAFIL, Mi Sistema, Perfil y Contacto.

## Cambio narrativo

TKOH deja de depender de una sucesión de screenshots y adopta la columna vertebral:

`CONTEXTO → PROBLEMA → RESPONSABILIDAD → CRITERIOS → DECISIONES → SISTEMA → EVIDENCIA / APRENDIZAJE`

La evidencia se jerarquiza así:

- **Prospectos V2:** decisión principal; prioridad, contexto y estados.
- **Cliente 360:** continuidad del contexto comercial.
- **Resumen:** lectura general antes del detalle.
- **Mi Trabajo / Empresas / Actividades:** continuidad de patrones entre módulos.
- **Manual comercial:** artefacto complementario, no prueba de outcome.

## Integridad de contenido

La implementación evita afirmar resultados que no cuentan con fuente o medición. No se incorporan claims de conversión, reducción de tiempos, productividad, validación con usuarios, ownership total del CRM ni resultados de negocio no documentados.

El estado del producto continúa presentado como `Iteración activa` y la evidencia de esta fase se describe como estructural.

## Jerarquía y densidad

Comparación de layout con RC13 mediante Chromium headless, CSS inline y la misma configuración de viewport:

| Viewport | RC13 · sistema escala | V1.2 RC1 | Cambio |
| --- | ---: | ---: | ---: |
| 1440 px | ~722 px | ~497 px | **-31.1%** |
| 1024 px | ~594 px | ~419 px | **-29.5%** |
| 768 px | ~2268 px | ~691 px | **-69.5%** |
| 430 px | ~1646 px | ~1070 px | **-35.0%** |
| 390 px | ~1549 px | ~1070 px | **-31.0%** |
| 360 px | ~1477 px | ~1091 px | **-26.2%** |
| 320 px | ~1391 px | ~1177 px | **-15.4%** |

El requisito explícito de ~30% de reducción en desktop queda cubierto a 1440 px. La composición mantiene `scrollWidth == innerWidth` en 320, 360, 390, 430, 768, 1024 y 1440 px.

El caso completo incorpora más razonamiento que RC13 y por ello no se reporta una reducción de altura total como si fuera un resultado conseguido. La reducción se concentra en la antigua secuencia redundante de tres módulos, mientras que el contenido nuevo se mantiene estructurado y escaneable.

## Accesibilidad

- Los nuevos bloques son contenido HTML visible; ninguna evidencia esencial depende de hover o click.
- Los seis screenshots de CR Master conservan `alt` significativo.
- Los nuevos labels TKOH parten de una base práctica de 12 px.
- Tablet/móvil mantienen orden de lectura antes de imagen.
- El modal PDF existente conserva su implementación y regresiones previas.
- `prefers-reduced-motion` y scroll nativo se mantienen; no se introduce pinning, scrub ni interceptación de scroll.

## Motion

`Build the System` se conserva como dialecto de TKOH:

- marco arquitectónico de Prospectos V2;
- reveal del producto y anotaciones;
- profundidad mínima en fine pointer;
- nuevas entradas reutilizan `observeOnce()` y Web Animations API existentes;
- las cards compactas reciben solo un lift restringido.

No se añade un subsistema de animación nuevo.

## Browser QA limitation

Chromium puede validar el layout mediante `page.set_content()` con CSS inline. La navegación directa a `file://` está bloqueada por la política del entorno, por lo que no se presenta una captura local como prueba de fidelidad completa del runtime servido. Las métricas de layout y overflow sí provienen de Chromium real.

Work no fue necesario para resolver RC1: la decisión de jerarquía ya estaba aprobada y las mediciones locales aportaron evidencia suficiente. Se reserva para decisiones visuales posteriores donde comparar alternativas pueda cambiar el rumbo.
