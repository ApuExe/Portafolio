# V1.1 RC3 — Intro reliability + native motion QA

## Root cause fixed
The black-screen symptom was not only a CDN/runtime issue. The cinematic root scrim (`html::before`) rendered at a higher stacking level than the isolated Hero stacking context, so the intro could animate correctly while remaining visually covered. RC3 explicitly places the Hero above the scrim and hides interface chrome during the cinematic sequence.

## Critical-path changes
- Intro animation no longer depends on GSAP or any external animation CDN.
- The Hero intro uses the browser Web Animations API.
- Prepaint state contains subtle visible motion instead of a featureless black frame.
- Prepaint fail-open timeout increased to 9 seconds and is no longer part of normal animation startup.
- Desktop target remains ~5.35 s; compact target remains ~3.90 s.
- `?intro=replay` still forces replay for review.
- Reduced-motion users skip the cinematic intro.

## Global life
A native IntersectionObserver reveal layer now preserves movement below the Hero even when GSAP is unavailable. Existing pointer proximity, structural line traces, metrics, system breathing, media hover and contact microinteractions remain active.

## Browser QA
Static-browser QA was executed in Chromium using the established inline-document workaround because direct localhost navigation is blocked by administrator policy in the environment.

Observed:
- Desktop intro: signals visible during SIGNAL/SATURATION, convergence visible, reveal resolves to final Hero.
- Mobile intro: active at 900 ms, Hero reveal active around 3.3 s, resolved around 4.3 s.
- No page errors observed in desktop or mobile QA runs.
